# ESA access for Content Share

`content.aryuki.cn` reaches the same Content Share Worker as `content.aryuki.com` through ESA and the `proxy-router` Worker. The frontend selects `accounts.aryuki.cn` only when its own origin is exactly `https://content.aryuki.cn`. The backend retains `PUBLIC_BASE_URL=https://content.aryuki.com` for direct requests and accepts the `.cn` origin only with a fresh HMAC proof generated by `proxy-router`. Both Workers must have the same `CONTENT_PROXY_ORIGIN_SECRET` secret. The Accounts app record `content-share` must have its `.cn` callback switch enabled; its registered `.com` callback remains in place.

## ESA rules

1. Keep the `content.aryuki.cn` proxied DNS record and set the HTTPS origin, origin Host, and origin SNI to `origin.aryuki.com`.
2. Add an ESA-to-origin request-header rule matching only `content.aryuki.cn`. Statically add `X-ESA-Target: content` and `X-ESA-Proxy-Key: <the existing ESA_PROXY_KEY value on proxy-router>`. Static Add must overwrite client-supplied values. Never expose this key to the browser or repository.
3. Bypass ESA cache for every `/api/*` request, including public API endpoints. Do not cache responses with `Set-Cookie` or any authenticated HTML.
4. Cache only versioned, public, identity-independent frontend assets under `/assets/*` for approximately seven days. Restrict the rule to GET and HEAD. The build uses hashed filenames, so new deployments get new asset URLs. Keep the document shell dynamic unless its headers and session behavior are reviewed separately.

## Protected content and transfers

Browser uploads use presigned PUT requests sent directly to R2, outside ESA and the proxy Worker. The bucket CORS rule in `r2-cors.json` must allow both exact page origins, `https://content.aryuki.com` and `https://content.aryuki.cn`. Apply it with `npx wrangler r2 bucket cors set content-share-save --file=./r2-cors.json`. Keep PUT and the existing permitted request headers; do not use a wildcard origin. If `.cn` uploads fail while API initiation succeeds, compare R2 OPTIONS preflight responses for the two origins.

Share metadata, text, previews, attachment downloads, and upload endpoints all use `/api/*`. Keep them out of ESA cache. The Worker checks visibility (`public`, `internal`, or `private`), owner and viewer permissions, passwords, expiry, maximum views, media tickets, and `allow_download` on the request path. A cached response could outlive a changed password, revoked permission, deleted share, or disabled download. Even a public attachment may later become protected. Upload POST/PUT and signed R2 transfer URLs must not be edge cached. Public static assets are the only file responses eligible for the seven-day ESA rule without a separate authorization design.

## Validation

Adobe PDF Embed uses a domain-bound Client ID. Configure the existing `ADOBE_PDF_CLIENT_ID` for `content.aryuki.com` and `ADOBE_PDF_CLIENT_ID_CN` for `content.aryuki.cn` as Worker Secrets. The `/api/public/pdf-embed-config` endpoint chooses the `.cn` ID only after validating the proxy's signed origin headers; the `.com` ID remains the direct-request default. If the selected ID is absent, the existing viewer falls back to PDF.js. The Client ID is sent to the browser by design; never put either value in repository files or logs. The API response remains `private, no-store` and must bypass ESA cache.

- `GET https://content.aryuki.cn/` should serve the app with `X-Applied-Rule: esa-content` and `X-Proxy-Status: Routed`.
- The login button on the `.cn` app should open `accounts.aryuki.cn` with a callback on `content.aryuki.cn/sso-callback`; the `.com` app should still use the `.com` pair.
- API responses should show a dynamic or bypass cache result. A second request for a hashed `/assets/*` URL may show an ESA hit.
- Test a protected share, an internal share, and an attachment with downloads disabled through `.cn`. Changes to access policy must take effect immediately.
